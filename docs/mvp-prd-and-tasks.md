# AI 面试复盘助手 MVP PRD 与开发任务清单

## 1. MVP 目标

第一版先做一个能实际使用的网页工具：用户登录后，粘贴中文面试文字稿，或上传 `.docx` / `.txt` / `.md` 自动提取文字，选择或填写岗位类型，填写岗位信息与 JD，点击生成复盘报告，并把历史报告保留下来，方便后续按岗位回看。

本版明确不做：

- 录音上传与自动转写
- 面试结果记录，例如通过、挂掉、等待反馈
- 多语言面试分析
- 复杂导出、练习任务、成本统计

## 2. 目标用户与场景

目标用户先按个人使用设计，未来可分享给朋友。典型使用频率是一周一次，密集面试期每天一到两次。

核心场景：

1. 面完后获得一份中文文字稿。
2. 新建或选择一个岗位项目。
3. 填写岗位类型、公司、岗位名称、轮次、JD。
4. 粘贴文字稿，或上传 `.docx` / `.txt` / `.md` 提取文字后生成复盘。
5. 查看百分制评分、问题拆解、优势不足和下一轮预测问题。
6. 登录后在历史记录中查看旧报告。

## 3. MVP 功能范围

### 3.1 登录

- 支持邮箱登录入口。
- 配置 Supabase 后使用 Supabase Auth。
- 本地开发未配置 Supabase 时，提供本地体验登录，便于马上试用。
- 当前已支持 Supabase 邮箱 Magic Link；下一阶段增加邮箱 + 密码登录，保留 Magic Link 作为备用入口。

### 3.2 岗位与复盘输入

必填：

- 岗位类型：运营、产品经理、数据分析、研发、设计、市场、其他。
- 岗位名称。
- 面试轮次。
- 中文文字稿。
- 可选上传 `.docx` / `.txt` / `.md` 自动提取文字稿，并尽量回填岗位类型、岗位名称、面试轮次和 JD。

建议填写：

- 公司名称。
- 岗位 JD。

### 3.3 AI 复盘报告

报告必须包含：

- 综合分，0-100 整数。
- 维度评分：逻辑、内容、表达、岗位匹配度，均为 0-100 整数。
- 面试官问题列表。
- 每个问题下的回答摘要、评分、问题点、改进建议、更好回答范例。
- 整场优势与不足。
- 高风险点与优先改进项。
- 下一轮预测问题。

评分规则：

- 综合分 = 逻辑 30% + 内容 35% + 表达 15% + 岗位匹配度 20%。
- 语气鼓励但具体，不用打击式评价。
- 不编造候选人没有说过的经历；信息不足时用占位符提醒补充。

### 3.4 历史保存

- 每次生成报告后自动保存到历史。
- 历史按当前用户保存在浏览器本地；接入 Supabase 后可保存到云端。
- 历史卡片展示岗位、公司、轮次、综合分、创建时间。
- 不记录面试结果。

## 4. 页面结构

### 4.1 工作台

- 顶部：应用名称、登录状态、配置状态。
- 左侧：输入表单和生成按钮。
- 右侧：当前报告概览、图表、问题复盘、预测问题。
- 底部或侧栏：历史记录列表。

### 4.2 报告详情

MVP 暂不拆独立路由，先在工作台内展示完整报告。后续再拆为 `/reports/[id]`。

## 6. 技术方案

- Next.js App Router
- React + TypeScript
- Tailwind CSS
- Recharts 图表
- OpenAI Responses API 分析文字稿
- Supabase Auth / Postgres 预留
- 本地体验模式使用 localStorage

环境变量：

- `OPENAI_API_KEY`
- `OPENAI_MODEL`
- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`

## 8. 验收标准

- 用户可以打开网页并登录到体验模式。
- 用户可以粘贴测试文字稿，填写岗位信息，生成报告。
- 报告展示综合分、维度分、逐题评分和预测问题。
- 用户生成报告后会自动保存，并可在历史记录里再次打开。
- 页面不要求配置 OpenAI Key 也能完成流程验证。
- 第一版界面不出现录音上传入口，不出现面试结果字段。
